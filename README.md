# Eventus - сервис для управления мероприятиями.
## Stack: ASP.NET Core, .NET 10.

### Eventus.WebApi
1. [GET] /api/events - возвращает список всех мероприятий по фильтру с пагинацией. 
2. [GET] /api/events/{id} - возвращает меропритие по его идентификатору.
3. [POST] /api/events - создаёт новое мероприятие.
4. [PUT] /api/events/{id} - обновляет мероприятие.
5. [DELETE] /api/events/{id} - удаляет мероприятие.

При отсутствии данных о мероприятии возвращается код 404 NotFound.

#### Спринт 2:
1. Реализована глобальная обработка исключений, унифицированный ответ в виде ProblemDetails ([RFC7807](https://datatracker.ietf.org/doc/html/rfc7807)).

   | Тип исключения            | Код ответа |
   |---------------------------|------------|
   | DomainValidationException | 400        |
   | NotFoundException         | 404        |
   | Любое другое              | 500        |

2. Добавлена фильтрация событий с пагинацией в методе [GET] api/events.

[GET] /api/events - возвращает список всех мероприятий по фильтру с пагинацией.
Параметры запроса GetEventsByFilterRequest:
  - Title - название события (поиск по подстроке)
  - From - левая граница даты допустимых событий 
  - To - правая граница даты допустимых событий
  - Page - номер страницы в ответе (от 1 до 100)
  - PageSize - максимальный размер страницы (от 1 до 100, реальный размер в ответе может быть меньше при отсутствии данных)

Формат ответа PaginatedEventsResultDto:
  - TotalCount - общее количество событий, удовлетворяющих фильтру 
  - Items - массив событий текущей страницы 
  - Page - номер текущей страницы
  - ItemsCount - количество событий на текущей странице

3. Добавлены тесты:
  - Unit тесты сервиса событий (Moq)
  - Unit тесты in-memory репозитория событий
  - Интеграционные тесты контроллера событий (WebApplicationFactory)

#### Спринт 3:
Добавлена модель бронирования *Booking* и модель выполнения асинхронной задачи процесса бронирования *BookingTask*.

*Booking*:  
Id - идентификатор бронирования,  
EventId - идентификатор события,  
Status - статус бронирования,  
CreatedAt - дата создания,  
ProcessedAt - дата обработки.

*BookingStatus*:  
Unknown = 0 - неизвестно,  
Pending = 1 - в ожидании,  
Confirmed = 2 - подтверждено,  
Rejected = 3 - отклонено.

*BookingProcessingException* - исключение, возникающее при обработке бронирования, когда событие обрабатывается не из статуса Pending либо когда то же бронирование уже было обновлено.

Добавлены новые эндпоинты:
1. [POST] /api/events/{id}/book - создаёт бронирование по идентификатору события.
2. [GET] /api/bookings/{id} - возвращает бронирование по его идентификатору.

Логика фоновой обработки:
1. При вызове метода [POST] /api/events/{id}/book создаётся черновик бронирования в статусе Pending и с текущей датой созданий CreatedAt. Клиент получает синхронный ответ в виде 202 Accepted: объект созданной брони и Location.
2. Создаётся задача для подтверждения бронирования и вставляется в очередь для дальнейшего асинхронного выполнения.
3. Фоновый сервис работает параллельно и проверяет очередь задач на наличие созданных бронирований, берёт текущую задачу и выполняет её.
4. Задача обновляет статус у бронирования на Confirmed и записывает дату ProcessedAt.
5. После завершения задачи при вызове метода [GET] /api/bookings/{id} возвращается бронирование с актуальными данными.

Особенности:
1. Для создания бронирования должно быть создано событие, которое необходимо забронировать. Если событие отсутствует, то при бронировании возвращается 404 NotFound. 
2. На данный момент выполняется имитация работы задачи подтверждения бронирования в виде задержки на 2 сек.
3. Обновление происходит атомарно при создании нового бронирования и полной замены существующего.
4. Подтвердить бронирование можно только из статуса Pending. При попытке подтвердить бронироание из другого статуса бросается BookingProcessingException.

### Запуск сервиса
Из корневой директории выполнить команды:
```
dotnet build
```

```
dotnet run --project ./Eventus.WebApi/Eventus.WebApi.csproj
```

### Запуск тестов
Из корневой директории выполнить команду:
```
dotnet test
```

Веб сервер будет доступен по адресу http://localhost:5240

Сваггер http://localhost:5240/swagger/index.html
